# Meridian — памятка проекта

> **Обязательное правило:** перед каждой задачей по Meridian сначала прочитай этот файл. Считай его постоянным источником требований к архитектуре, поведению, визуальному языку и качеству. Не заменяй требования собственными предположениями и не упрощай их молча. Если новый запрос явно меняет правило из памятки, выполняй изменение в пределах этого запроса и учитывай его далее.

## 1. Идея и название

**Название продукта — только Meridian.** Это спокойная среда для занятий по трём маршрутам: английский, шахматы и Python. Меридиан — единая ось, по которой ученик проходит три предмета. Это не «умная платформа» и не AI-тьютор.

Запрещены приставки и переименования вроде AI, GPT, Neural, Smart, Pro, Cloud, Hub, Lab; не придумывать аббревиатурную расшифровку. В интерфейсе, заголовках, README и логотипе использовать Meridian. Prism, Lyra и Cairn допустимы только как запасные названия при реальном конфликте имени и после согласования.

Тон: спокойный, навигационный, ясный. Интерфейс — на русском. Английский используется как изучаемый материал; Python-код и ключевые слова — на английском, объяснения — на русском.

## 2. Технологии и ограничения

- Статический SPA для GitHub Pages: **vanilla JavaScript (ES-модули), CSS и JSON**.
- Никаких фреймворков, сборщиков и обязательного Node.js на продакшене.
- Внешняя зависимость — только локальная `/lib/chessboard.min.js`.
- Все уроки и карточки предметов загружаются из `/data/*.json`; не хардкодить в JS большие наборы учебных данных.
- Поддерживать запуск через локальный HTTP-сервер и GitHub Pages. Не обещать работу `fetch()` при открытии через `file://`.
- Не выполнять произвольный код пользователя. Запрещены `eval`, `new Function` и аналогичные способы исполнения.
- Никаких inline-`onclick`: обработчики подключать через `addEventListener`.
- Не добавлять зависимости «на будущее», мёртвый код или неиспользуемые функции.

### Shell и маршрутизация

- `index.html` — только оболочка: `lang="ru"`, meta viewport, `<title>Meridian — английский, шахматы, Python</title>`, `<div id="app" aria-label="Meridian">` и подключение `/js/main.js` с `type="module"`. Не размещать в shell логику предметов.
- `404.html` — восстановление hash-маршрута для GitHub Pages с возвратом в SPA.
- Hash-маршруты: `#/`, `#/english`, `#/chess`, `#/python`.
- `router.js` слушает `hashchange` и отображает в `#app` один экран за раз. Неизвестный маршрут должен безопасно обрабатываться.
- Главный экран — компактный учебный дашборд: шапка Meridian, три предметных маршрута, фактический прогресс и кнопка продолжения только при валидной сохранённой сессии. Это не лендинг и не hero-экран.
- Переход экрана: лёгкие `opacity` и `translateY(8px)` с `--dur-base` и `--ease-out`.

## 4. Данные и логика предметов

### 4.1 Английский (RU → EN, SM-2)

Источник: `/data/english-deck.json`. Не менее 12 реальных карточек единой схемы:

```json
{ "ru": "доброе утро", "en": "good morning", "example": "Good morning, everyone." }
```

Экран показывает русское слово или фразу, поле ввода либо выбор ответа и кнопку «Проверить». После ответа показываются правильный вариант и пример, затем четыре оценки: Again, Hard, Good, Easy.

Реализовать SM-2; для каждой карточки хранить объект `{ ease, interval, due, repetitions }` в `mrd:english:progress`. Оценки должны последовательно менять интервал, дату следующего повторения и число повторений. Не назначать фиктивный прогресс.

Сессия `mrd:english:session` содержит `{ currentCardIndex, deckFilter }` и сохраняется при каждом переходе между карточками/состояниями. На главной показывать «Продолжить английский» только если объект сессии корректен и указывает на существующую карточку.

Анимация карточки: переворот `rotateY(180deg)`, `--dur-base`, `--ease-out`. При верном ответе допустим короткий pulse кнопки проверки: `scale(1) → 1.06 → 1`, 200 ms, `--ease-overshoot`. Не анимировать буквы и не трясти экран.

### 4.2 Шахматы (объяснения на русском)

Источник: `/data/chess-lessons.json`. Не менее 6 проверенных уроков единой схемы:

```json
{
  "id": "notation",
  "title": "Шахматная нотация",
  "text": "Краткое корректное объяснение.",
  "quiz": [{ "q": "Вопрос", "options": ["Вариант A", "Вариант B", "Вариант C"], "answer": 0 }]
}
```

Покрыть как минимум темы: доска и координаты/нотация, ходы фигур, взятие, шах и мат, рокировка, мат в один ход. Не выдумывать правила; проверять формулировки и ответы. Мини-тесты имеют три варианта ответа.

Показывать список уроков и реальный статус завершения. Завершённые уроки хранить массивом ID в `mrd:chess:completed`; выбранный урок — в `mrd:chess:session`.

Для визуализации ходов использовать локальную `chessboard.min.js` и предусмотренный интерфейс `board.movePiece(move, { animate: true })`, если он доступен в используемой сборке. Сначала проверить фактический API библиотеки: не предполагать, что произвольная версия chessboard.js имеет метод `movePiece`. Если скрипт, API или ресурс не загрузился, показать статичную доску/позицию и текстовое объяснение; экран урока должен оставаться рабочим, консоль не должна заполняться ожидаемыми ошибками отсутствующей библиотеки.

При завершении урока полоса прогресса заполняется до 100% за `--dur-slow`, затем один раз вызывается `celebrate()` с длительностью 800 ms. Не показывать повторную celebration при каждом рендере уже завершённого урока.

### 4.3 Python (короткие интерактивные уроки)

Источник: `/data/python-lessons.json`. Не менее 4 уроков: `print`, переменные, условия, цикл. Единая схема:

```json
{
  "id": "print",
  "title": "Вывод текста",
  "theory": "Объяснение на русском.",
  "starterCode": "print(\"Hello, world!\")",
  "expectedOutput": "Hello, world!"
}
```

Экран урока: теория и инструкция слева/сверху, редактор `<textarea>` с моноширинным шрифтом справа/ниже, кнопка «Run» или «Проверить». На адаптивном экране колонки складываются вертикально.

Проверка строго сопоставляет `textarea.value.trim()` с `expectedOutput.trim()`. Это проверка заранее заданного ответа, а не интерпретатор: **не исполнять** введённый код и не использовать `eval`/динамическое выполнение. Объяснять, что исправить, если вывод не совпал.

Завершённые ID хранить в `mrd:python:completed`. Сессия `mrd:python:session` содержит текущий `lessonId` и черновик кода; сохранять изменения и восстанавливать их при продолжении. Успешный ответ кратко подтверждается; прогресс урока заполняется. Полноэкранная celebration допускается только при первом завершении всего модуля, а не при каждом правильном упражнении.

## 5. Сохранение состояния

Все ключи localStorage обязаны начинаться с **`mrd:`**. Не использовать другие корневые префиксы и случайные имена ключей.

Минимальные ключи:

- `mrd:english:progress` — SM-2 состояние карточек;
- `mrd:english:session` — `currentCardIndex`, `deckFilter`;
- `mrd:chess:completed` — массив ID завершённых уроков;
- `mrd:chess:session` — текущий ID урока;
- `mrd:python:completed` — массив ID завершённых уроков;
- `mrd:python:session` — ID урока и черновик кода.

Сделать общий слой в `storage.js`: безопасный parse, проверка/нормализация формы данных, обработка отсутствующих или повреждённых значений, запись в try/catch. Сохранения не должны ломать приложение при недоступном localStorage или некорректном JSON. Не показывать «Продолжить», если сессия невалидна. Прогресс на главной всегда вычислять по сохранённым данным относительно реального числа карточек/уроков.

## 6. Единая motion-система

Единственные общие токены движения определяются в `css/tokens.css`:

```css
--dur-fast: 100ms;
--dur-base: 250ms;
--dur-slow: 400ms;
--dur-celebrate: 800ms;
--ease-out: cubic-bezier(0.25, 1, 0.5, 1);
--ease-overshoot: cubic-bezier(0.34, 1.56, 0.64, 1);
```

Использовать токены во всех CSS-модулях. `motion.js` экспортирует как минимум `prefersReducedMotion()` и `celebrate()`. Celebration длится 600–1200 ms (типовая длительность — 800 ms); при `prefers-reduced-motion: reduce` остаётся статичное текстовое подтверждение без сложного движения.

Разрешено анимировать `transform` и `opacity`; исключение — аккуратное заполнение progress bar через `width`. Не анимировать в циклах `height`, `top`, `left`, `margin` и другие параметры геометрии. Для успеха Python можно использовать краткое визуальное подтверждение редактора, но не превращать его в бесконечную пульсацию.

Не более 2–3 повторяющихся motion-паттернов на сайт. Никаких бесконечных анимаций, «дыхания» фона, парящих объектов, параллакса ради эффекта, тряски, вращения логотипа. Не более одного celebration-акцента на экран. Конфетти/крупное поздравление — только при завершении модуля, не на каждый ответ.

В `base.css` обязательно:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 7. Визуальный язык — Anti-AI-slop

При сомнении выбирать уместность, ясность и доступность, а не эффектность.

### Цвет и поверхности
- Запрещены фиолетово-синие градиенты, неон, кислотный cyan, «магические» градиенты, mesh/noise-фоны и декоративные blob-формы.
- Не применять повсеместный glassmorphism, blur-карточки, полупрозрачные панели и светящиеся обводки.
- Использовать спокойную базовую палитру: фон, поверхность, текст, один различимый акцент на предмет, семантические success/error.
- Контраст текста — не ниже WCAG AA.
- Одна последовательная система теней/elevation, без случайных теней для каждого элемента.

### Форма и типографика
- Радиусы карточек ориентировочно 12–16 px, кнопок 8–10 px; не делать всё скруглённым на 24 px и более.
- Сетка отступов кратна 4/8 px; случайные числа вне токенов не вводить.
- Не более двух семейств шрифтов; понятная типографическая шкала; line-height основного текста не меньше 1.4.
- Никакого градиентного текста и гигантских заголовков на весь экран.

### Иконки и предметная подача
- Не использовать эмодзи как иконки. Иконки — SVG из `/assets/icons/`, единый stroke/fill и согласованный размер.
- Английский: ощущение бумажных карточек и ясная типографика.
- Шахматы: доска, координаты, фигуры и нотация.
- Python: сдержанный редактор/терминал и моноширинный код.
- Не копировать Duolingo и его фирменных персонажей/ассеты; можно использовать только общие учебные механики.
- Не делать трёхколоночную карточную сетку единственным паттерном. Визуальная иерархия должна отражать сценарий «предмет → урок → задание».
- Не использовать абсолютное позиционирование для основного потока контента.

## 8. Текст и учебный контент

- Запрещены lorem ipsum, заглушки типа «Текст урока», выдуманные примеры и редкие слова без контекста.
- Английские предложения должны быть естественными и подходить к значению карточки.
- Шахматные правила должны быть точными; ответы тестов должны совпадать с объяснениями.
- Python `expectedOutput` должен быть вручную проверен на соответствие правильному учебному примеру.
- Интерфейсные подписи короткие и человеческие: «Проверить», «Дальше», «Повторить», «Продолжить английский».
- Ошибки объяснять по делу: указать, что неверно и как исправить.
- Не использовать AI-штампы: «Unlock your potential», «Elevate your learning», «Seamless», «Revolutionary», «AI-powered», «Delve», «Game-changer», «Next-level».
- Не придумывать отзывы, рейтинги, число учеников, лидерборды, достижения или прогресс.
- Не вводить ложный дефицит, искусственные таймеры и давление сериями/стрика́ми, если такая механика отдельно не согласована.

## 9. Доступность, адаптивность и состояния

Приоритет при конфликте: **доступность → ясность → визуальная цельность → анимация → декоративность**.

- Видимый keyboard focus; все основные действия доступны с клавиатуры.
- Использовать семантические элементы, корректные labels и `aria-label` там, где назначение элемента неочевидно.
- Не прятать важную информацию за hover.
- Поддерживать ширины 360 px, 768 px и 1280 px; горизонтальный скролл не допускается.
- На малых экранах двухколоночные области переходят в один столбец.
- Предусмотреть понятные состояния loading, empty, error и success.
- Ошибка загрузки JSON должна приводить к понятному сообщению в интерфейсе, а не к пустому экрану/падению всего приложения.
- Если chessboard недоступна, статическое представление и текст сохраняют смысл урока.
- При reduced motion отключать сложные движения и оставлять статичное подтверждение.

## 10. Качество кода

- Имена функций/переменных должны описывать назначение: `saveEnglishSession`, `renderChessLesson`, `checkPythonOutput`.
- Общие кнопки, карточки, прогресс-бары и состояния оформлять централизованно в `components.css`; не дублировать CSS-блоки.
- Токены дизайна и motion — в `tokens.css`; базовая типографика, reset и reduced motion — в `base.css`; структура страниц — в `layout.css`.
- Не использовать магические числа там, где подходит CSS-токен или именованная константа.
- Не оставлять `console.log` в финальном коде. Допустим только осмысленный `console.error` внутри обработки ошибки.
- Комментарии добавлять только для неочевидных решений.
- Ошибки fetch/JSON/storage обрабатывать и давать пользователю понятный путь продолжения.

## 12. Acceptance checklist перед завершением любой задачи

Перед тем как считать изменение готовым, проверить применимые пункты:

1. В `<title>`, шапке и README используется только имя Meridian.
2. Каждый localStorage key начинается с `mrd:`; прогресс и сессии сохраняются для всех затронутых модулей.
3. Учебные данные лежат в правильном JSON-файле и соответствуют единой схеме.
4. Нет lorem ipsum, выдуманного прогресса, фальшивых отзывов/цифр и AI-штампов.
5. Главная выглядит как компактный учебный дашборд, не как лендинг.
6. Нет запрещённых градиентов, glassmorphism, blob’ов, неона или эмодзи-иконок.
7. Анимации используют motion-токены и в основном `transform`/`opacity`; progress bar — единственное осознанное исключение для `width`.
8. `prefers-reduced-motion` учитывается CSS и `motion.js`; celebration не чаще одного раза на экран и длится 600–1200 ms.
9. Прогресс вычисляется из валидных сохранённых данных; кнопка продолжения показывается только при валидной сессии.
10. Нет `eval`, `new Function`, inline-`onclick`, произвольного исполнения Python или лишних зависимостей.
11. Видим фокус, основные элементы доступны с клавиатуры, ошибки и пустые состояния объяснены.
12. Проверены адаптивность 360/768/1280 px, загрузка JSON и fallback для недоступной шахматной библиотеки.
13. README содержит действующие шаги деплоя GitHub Pages: `main` / `root`.
14. Код остался разбит по файлам; обновление не свалило логику проекта в `index.html`.

**Правило для будущей работы:** сначала прочитать эту памятку и актуальные файлы репозитория; затем внести минимальные согласованные изменения; после — проверить diff и применимые пункты Acceptance checklist.

## 13. Meridian V2 — уточнения реализации

Эти уточнения дополняют разделы выше и фиксируют фактический V2-поток:

- Главная показывает отдельный блок «Продолжить» выше предметных карточек только для валидных сохранённых сессий. Для английского учитывается выбранный фильтр и текущая карточка; для шахмат — существующий ID урока; для Python — существующий ID урока и строковый черновик.
- Английская сессия использует карточки с наступившим сроком и новые карточки. После ответа показываются перевод и пример; четыре оценки SM-2 меняют ease, interval, due и repetitions. Прогресс главной считается по валидным сохранённым записям карточек.
- Каждый шахматный урок содержит FEN. Локальная доска Meridian поддерживает доступность клеток с клавиатуры и визуальное перемещение. Выбор коня, слона или ладьи подсвечивает геометрически доступные поля; подсказка не заменяет проверку шаха и полного правила легальности. При недоступности библиотеки используется статичная доска с тем же взаимодействием.
- Шахматные вопросы привязаны к показанным позициям и демонстрируемым ходам. При первом правильном завершении урока прогресс заполняется, затем один раз появляется celebration длительностью 800 ms.
- Python использует ограниченный учебный исполнитель только для print(), простого присваивания строк/чисел, числовых if/else и for по range(). Он не исполняет произвольный Python, импорты, файловые операции, сеть или системные команды. expectedOutput содержит ожидаемый вывод, а интерфейс сравнивает фактический вывод построчно и показывает первое расхождение.
- Подсказка Python доступна после первой неудачной попытки; попытки хранятся в mrd:python:attempts. Черновик хранится в mrd:python:session. Для цикла вывод показывается построчно.
- Все новые CSS-правила остаются в components.css/layout.css; общие motion-токены не меняются. При изменении структуры главной stagger применяется к предметным карточкам, а не к блоку продолжения.


## 14. Meridian V3 — иерархия учебной программы

Этот раздел фиксирует V3 и уточняет V2 там, где они расходятся. V3 сохраняет vanilla JS ES-модули, CSS/JSON, GitHub Pages без production build и общий визуальный язык.

### Структура и маршруты

- Маршруты: `#/english`, `#/chess`, `#/python`; юнит: `#/<module>/<unitId>`; урок: `#/<module>/<unitId>/<lessonId>`.
- Каждый модуль имеет `data/<module>/curriculum.json` с метаданными юнитов.
- Каждый юнит загружается отдельно из `data/<module>/units/<unitId>.json`. Содержимое юнита не загружается на главном экране модуля до открытия юнита; поиск может лениво загрузить нужные файлы, чтобы искать по названиям уроков и тегам.
- Стабильные ID обязательны: `unitId`, `lessonId`, для английских карточек — `card.id`. Никаких привязок прогресса к индексам массивов.
- В текущей ветке V3: 15 юнитов × 4 урока в каждом модуле; 60 уроков английского, 60 шахматных и 60 Python. Английский содержит 600 карточек.

### Форматы содержимого

- English lesson: `lessonId`, `unitId`, `order`, `title`, `estimatedMinutes`, `tags`, `content.cards[]`; каждая карточка содержит `id`, `ru`, `en`, `example`, `tags`.
- Chess lesson: `lessonId`, `unitId`, `order`, `title`, `text`, `fen`, `quiz[]`; тест имеет 3–6 вариантов и корректный индекс ответа. FEN отображается на доске; позиция должна содержать ровно одного белого и чёрного короля и 8 корректно заполненных горизонталей.
- Python lesson: `lessonId`, `unitId`, `order`, `title`, `theory`, `starterCode`, `expectedOutput`, `hint`; `exampleInput` допустим для фиксированных примеров ввода.

### Прогресс и миграция

- V3 использует `mrd:english:srs` для SM-2 по стабильным ID карточек; `mrd:english:completed`, `mrd:chess:completed`, `mrd:python:completed` содержат ID завершённых уроков.
- Сессии модулей содержат `unitId` и `lessonId`; Python также сохраняет `draftCode`. `mrd:lastLesson` указывает последний открытый урок.
- Совместимые старые ID шахматных и Python-уроков мигрируются добавлением соответствующих V3 ID. Старые записи не удаляются. Старые English SM-2 индексы остаются нетронутыми, поскольку индексы V2 нельзя безопасно сопоставить карточкам V3 без сравнения содержания.
- Все операции чтения/записи проходят через `storage.js`; все ключи имеют префикс `mrd:`.

### Безопасный Python runner

V3 не запускает произвольный Python и не использует `eval`/динамическое выполнение. Учебный интерпретатор ограничен контролируемым подмножеством: строки и числа, bool, input с фиксированным `exampleInput`, простые присваивания, списки/кортежи/словари/множества, индексация и базовые методы, сравнения if/else, ограниченные for/range и while со счётчиком, пользовательские функции, аргументы, return и lambda. Импорты, файловая система, сеть, системные команды и динамическое исполнение запрещены. Текстовые файлы представлены виртуальными строковыми данными; упражнения не читают и не изменяют файлы устройства.

### Проверка перед публикацией

- Проверить все 15 unit-файлов каждого модуля на соответствие манифестам.
- Проверить уникальность unitId, lessonId и английских card.id.
- Проверить 600 карточек, 60 шахматных FEN и тесты, 60 Python-заданий и ожидаемые результаты.
- Проверить миграцию V2, возобновление сессий и сохранение Python-черновиков.
- Проверить 360/768/1280 px, keyboard focus, reduced motion, ошибки загрузки и GitHub Pages base path.
- Не считать V3 визуально проверенной, пока не выполнен реальный браузерный прогон.
