# Meridian — постоянная памятка проекта

> Перед любой задачей по этому репозиторию сначала прочитай этот файл целиком. Считай его постоянной спецификацией проекта и сверяй с ним архитектуру, интерфейс, код и новые функции. Не меняй принципы проекта молча.

## 1. Идентичность и назначение

- Название продукта и единственное имя в интерфейсе: **Meridian**.
- Meridian — спокойная учебная среда с одной общей осью и тремя маршрутами: английский, шахматы, Python.
- Не добавляй к названию AI, GPT, Neural, Smart, Pro, Cloud, Hub, Lab и не придумывай расшифровку.
- Тон интерфейса: спокойный, ясный, навигационный. Это не «умная платформа» и не «AI-тьютор».
- Основной язык интерфейса и объяснений — русский. Английский используется в изучаемом материале, Python — в коде и ключевых словах.
- Приоритет при любом конфликте требований: **доступность → ясность → визуальная цельность → анимация → декоративность**.

## 2. Технологии и архитектура

- Проект — статический SPA для GitHub Pages, без этапа сборки и без Node.js на продакшене.
- Используй только HTML, CSS, vanilla JavaScript (ES-модули) и JSON. Не подключай фреймворки и сторонние библиотеки, кроме локальной шахматной библиотеки.
- ES-модули разделяют маршрутизацию, хранение, motion и предметную логику без глобального пространства имён; данные предметов хранятся отдельно в JSON.
- Рекомендуемая структура:

  ```text
  /
  ├── index.html
  ├── 404.html
  ├── README.md
  ├── AGENTS.md
  ├── css/
  │   ├── tokens.css
  │   ├── base.css
  │   ├── layout.css
  │   └── components.css
  ├── js/
  │   ├── main.js
  │   ├── router.js
  │   ├── storage.js
  │   ├── motion.js
  │   └── modules/
  │       ├── english.js
  │       ├── chess.js
  │       └── python.js
  ├── data/
  │   ├── english-deck.json
  │   ├── chess-lessons.json
  │   └── python-lessons.json
  ├── lib/
  │   └── chessboard.min.js
  └── assets/
      └── icons/
  ```

- Разделяй код по назначению. Не превращай проект обратно в один большой HTML-файл.
- `index.html` — только shell: `<div id="app" aria-label="Meridian"></div>`, метаданные, русский язык, заголовок страницы и подключение главного ES-модуля.
- Важно для GitHub Pages: проект часто открывается по адресу `https://<username>.github.io/<repo>/`, а не из корня домена. Поэтому пути к скриптам, стилям и JSON должны корректно работать из подпапки репозитория: предпочитай относительные пути или вычисляй URL от `import.meta.url`. Не используй корневые пути вида `/js/main.js` и `/data/file.json`, если они ломают deploy в подпапке.
- Hash-маршруты: `#/`, `#/english`, `#/chess`, `#/python`. `router.js` слушает `hashchange` и рендерит выбранный экран в `#app`.
- Ошибка загрузки одного JSON или библиотеки не должна ронять всё приложение. Показывай понятное состояние ошибки или безопасный статичный fallback.
- `404.html` должен возвращать пользователя к SPA с сохранением hash-маршрута и корректной работой в подпапке GitHub Pages.

## 3. Хранение и прогресс

- Все ключи localStorage обязаны начинаться с префикса `mrd:`. Не используй другие префиксы и случайные ключи.
- Вынеси чтение, запись, проверку и обработку ошибок хранилища в `js/storage.js`.
- Не доверяй повреждённым или устаревшим данным: безопасно обрабатывай JSON parse errors и проверяй структуру сессии перед показом «Продолжить».
- Сохраняй прогресс и незавершённую сессию по ходу работы, а не только при закрытии страницы.
- Обязательные ключи:
  - `mrd:english:progress` — объект прогресса карточек: `ease`, `interval`, `due`, `repetitions`.
  - `mrd:english:session` — `currentCardIndex`, `deckFilter`.
  - `mrd:chess:completed` — массив завершённых `lessonId`.
  - `mrd:chess:session` — текущий урок.
  - `mrd:python:completed` — массив завершённых `lessonId`.
  - `mrd:python:session` — текущий `lessonId` и черновик кода.
- Главный экран показывает только фактически вычисленный прогресс. Кнопка продолжения появляется, только если сохранённая сессия существует и прошла валидацию.
- Не подменяй отсутствие данных фейковыми процентами, сериями, наградами или достижениями.

## 4. Модуль «Английский (RU→EN)»

- Источник контента: `data/english-deck.json`. Не зашивай большие наборы карточек в JavaScript.
- Минимум 12 содержательных карточек формата `{ "ru": "...", "en": "...", "example": "..." }`.
- Экран показывает русское слово или фразу, поле ввода либо выбор ответа и кнопку «Проверить».
- После проверки покажи корректный ответ и естественный пример, затем четыре оценки: Again, Hard, Good, Easy.
- Реализуй интервальное повторение SM-2; состояние каждой карточки хранит `ease`, `interval`, `due`, `repetitions` в `mrd:english:progress`. Правила переходов и оценок должны быть единообразными; не меняй расписание карточки до выбора самооценки.
- Сохраняй `currentCardIndex` и `deckFilter` в `mrd:english:session` при переходах.
- Переход карточки: переворот `rotateY(180deg)` за `--dur-base` с `--ease-out`. Правильный ответ может дать один короткий отклик кнопки; не анимируй отдельные буквы и весь экран.

## 5. Модуль «Шахматы (RU)»

- Источник: `data/chess-lessons.json`, минимум 6 уроков формата `{ "id", "title", "text", "quiz": [{ "q", "options", "answer" }] }`.
- Темы как минимум: шахматная нотация, ходы фигур, рокировка, мат в один ход. Правила должны соответствовать обычным шахматным правилам; не изобретай исключения.
- Список уроков показывает реальный прогресс. Урок содержит объяснение и мини-тест с тремя вариантами ответа.
- Для доски используй только локальную `lib/chessboard.min.js`. Анимацию ходов выполняй через предусмотренный библиотекой API; если библиотека поддерживает `board.movePiece(move, { animate: true })`, используй его. При отсутствии или ошибке загрузки покажи статичную доску и текстовое объяснение без падения приложения и без шумных ошибок в консоли.
- Завершение урока: progress bar заполняется до 100% за `--dur-slow`, после чего вызывается `celebrate()` с длительностью по motion-системе.
- Сохраняй завершённые ID в `mrd:chess:completed`, текущий урок — в `mrd:chess:session`.

## 6. Модуль «Python»

- Источник: `data/python-lessons.json`, минимум 4 урока формата `{ "id", "title", "theory", "starterCode", "expectedOutput" }`.
- Темы: `print`, переменные, условия, циклы. Теория краткая и на русском; код и ключевые слова — Python.
- Экран урока: теория, моноширинный редактор на базе `textarea`, кнопка «Run», область результата и понятная обратная связь.
- Не запускай Python, JavaScript или произвольный код пользователя. Не используй `eval`, `new Function`, интерпретаторы в браузере или серверный запуск.
- Проверка в этой версии — только сравнение `textarea.value.trim()` с `expectedOutput.trim()`. Контент тестов должен быть согласован: ожидаемый вывод обязан соответствовать стартовому примеру.
- При успехе покажи краткое подтверждение и обнови прогресс. Эффекты не должны отвлекать от кода; соблюдай общую motion-систему.
- Сохраняй завершённые ID в `mrd:python:completed`, а текущий `lessonId` и черновик редактора — в `mrd:python:session`.

## 7. Единая motion-система

- Все motion-токены живут в `css/tokens.css`; используй их, а не разрозненные значения в предметных модулях:
  - `--dur-fast: 100ms`
  - `--dur-base: 250ms`
  - `--dur-slow: 400ms`
  - `--dur-celebrate: 800ms`
  - `--ease-out: cubic-bezier(0.25, 1, 0.5, 1)`
  - `--ease-overshoot: cubic-bezier(0.34, 1.56, 0.64, 1)`
- Общие функции и проверка `prefers-reduced-motion` находятся в `js/motion.js`.
- Обязательно реализуй `prefersReducedMotion()` и `celebrate()`. Celebration длится 600–1200 ms (обычно 800 ms); при reduced motion — только статичное или текстовое подтверждение.
- Основные анимации — только `transform` и `opacity`. Изменение `width` допустимо только для заполнения progress bar. Не анимируй layout-свойства.
- В `base.css` обязательно:
  `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; } }`
- Не более 2–3 повторяющихся паттернов motion на весь сайт и не более одного celebration-акцента на экран. Никаких бесконечных пульсаций, «дыхания» фона, вращения логотипа, тряски экрана и конфетти за каждый ответ. Крупная celebration допустима только при завершении всего модуля.

## 8. Визуальный язык и Anti-AI-slop

- Арт-направление — спокойная, собранная учебная среда, без лендинговой подачи.
- Главная — компактная шапка Meridian и учебный дашборд с тремя предметными маршрутами, вычисляемым прогрессом и доступными действиями продолжения.
- Для английского используй ассоциации с бумажными карточками и ясной типографикой; для шахмат — доску, координаты и нотацию; для Python — редактор и терминальные элементы.
- Палитра: нейтральная основа и поверхности, отдельный сдержанный акцент каждого предмета, семантические цвета успеха и ошибки. Контраст основного текста — не ниже WCAG AA.
- Не используй фиолетово-синие AI-градиенты, неон, кислотный cyan, стеклянные карточки, blur, glowing borders, floating blobs, mesh/noise backgrounds и градиентный текст.
- Иконки — SVG в `assets/icons/` с единым stroke/fill. Не используй эмодзи как иконки.
- Скругления единообразны: карточки ориентировочно 12–16 px, кнопки 8–10 px. Одна понятная система теней и elevation.
- Не более двух семейств шрифтов, понятная типографическая шкала, line-height основного текста не ниже 1.4. Отступы — по шкале 4/8 px и токенам.
- Не копируй Duolingo или чужие фирменные элементы. Можно использовать общую механику карточек и уроков, но визуальный язык Meridian должен оставаться оригинальным.
- Запрещены фейковые отзывы, рейтинги, число учеников, лидерборды, награды, ложный дефицит, искусственные таймеры и AI-штампы вроде “Unlock your potential”, “Seamless”, “Game-changer”.
- Микрокопия короткая и естественная: «Проверить», «Дальше», «Повторить», «Продолжить английский». Ошибки объясняют, что случилось и что исправить.

## 9. Доступность и адаптивность

- Проверяй ширины 360 px, 768 px и 1280 px. Не допускай горизонтального скролла.
- Все действия доступны с клавиатуры; видимый focus state обязателен.
- Поля, кнопки, интерактивные доски и корневой контейнер имеют осмысленные доступные подписи; используй aria-label там, где видимый текст не объясняет назначение.
- Не прячь важный контент за hover. Используй семантические элементы, логичный порядок фокуса и достаточный контраст.
- Предусмотри понятные состояния loading, empty, error и success. Пустой экран без объяснения недопустим.
- Уважай `prefers-reduced-motion` не только в CSS, но и в JavaScript-функциях motion.

## 10. Правила реализации и проверки

- События назначай через `addEventListener`; inline `onclick` запрещён.
- Не используй `eval`, `new Function`, выполнение произвольного кода, неиспользуемые зависимости и мёртвые функции.
- Не оставляй `console.log` в финальном коде. `console.error` допустим только для осознанной обработки ошибки.
- Выноси повторно используемые кнопки, карточки и progress bar в общие компоненты CSS. Не дублируй стили между модулями.
- Магические числа и motion-значения заменяй именованными константами или CSS-токенами.
- Комментарии оставляй только для логики, которую нельзя понять из кода и названий.
- После каждой заметной задачи проверяй: маршруты; загрузку JSON; восстановление сессий; корректный подсчёт прогресса; отсутствие ошибок при недоступной шахматной библиотеке; Python-проверку без исполнения кода; клавиатурную навигацию; reduced motion; адаптивность.
- Если требование из старого промпта технически мешает корректной работе GitHub Pages или доступности, сохрани исходную цель и выбери совместимую реализацию. Объясни такое отклонение в ответе; не изменяй продуктовую концепцию.
- Если пользователь явно меняет требование, следуй его последнему прямому указанию, но не считай случайное предположение разрешением убрать остальные правила.

## 11. GitHub Pages и документация

- README должен называться **Meridian**, кратко описывать три предметных модуля и объяснять локальный запуск через простой HTTP-сервер.
- Обязательный раздел README: **Deploy to GitHub Pages** — включить Pages, выбрать ветку `main` и папку root, затем открыть `https://<username>.github.io/<repo>/`.
- Перед публикацией проверь все ссылки на CSS, JS, JSON, иконки и локальную шахматную библиотеку именно из URL проекта в подпапке.
- Не добавляй build steps и требования к Node.js для production deploy.
